# 子代理タスク委任（Sub-Agent Delegation）

> 2026-08-29 新設。制作パイプラインの単純作業を低コストモデルに委任し、高価なメインモデルは判断・執筆・統合に集中する。

---

## 原則

1. **判断が要る仕事はメインモデル、作業が中心の仕事はサブエージェント（低コストモデル）**
2. サブエージェントの結果は**必ずメインモデルが検証**してから次工程へ渡す（検証パスなしで探す結果を直接使わない）
3. サブエージェントは**ステートレス**（前回の文脈を持ち越さない）。必要な文脈はプロンプトに明示する

---

## 委任対象タスク

| タスク | 入力 | 期待出力 | モデル層 | 検証方法 |
|--------|------|----------|----------|----------|
| **検索結果の評価・選別** | Web 検索 / SearXNG / Wikimedia API の結果一覧 | 品質スコア付きの上位 N 件 + 除外理由 | 低コスト（flash/mini クラス） | メインモデルが上位3件を目視確認 |
| **画像の品質評価・選択** | 候補画像 URL とメタデータ（解像度・ファイルサイズ） | 品質判定（高/中/低）+ 推奨1枚 | 低コスト | 解像度とファイルサイズの閾値チェック（自動） |
| **素材の一次スクリーニング** | `collection/` の素材ファイル一覧 | カテゴリ・優先度の仮振り | 低コスト | Phase 1 の採点でメインモデルが再評価 |
| **TTS テキストの正規化結果確認** | 正規化前後の diff | 違反パターンの検出報告 | 低コスト | `check_japanese.py` の PASS/FAIL（自動） |
| **画像のダウンロード実行** | 確定した URL リスト | ローカル保存完了報告 | 低コスト（スクリプト実行のみ） | ファイル存在 + サイズ閾値チェック（自動） |
| **時刻・数値の整合性チェック** | 素材本文 vs draft の抜粋 | 数値の不一致検出報告 | 低コスト | メインモデルが不一致箇所を確認 |

## 委任しないタスク

| タスク | 理由 |
|--------|------|
| テーマの採点・選定（Phase 1） | 番組の質を決める最大の分岐点。総合判断が必要 |
| ナレーションの執筆・書き直し（Phase 2） | 情報密度・日本語品質・投資判断の質が直接保証されるべき |
| B テーマの終選 | 25-40 分窓の判断は編集方針そのもの |
| 視覚設計ブリーフの作成 | 内容理解と視覚化の橋渡し。文脈把握が必要 |
| segment-map の切り分け | 音画同期の正確性に直結。全編の理解が必要 |
| Gate 判定（全 Gate） | 合否の責任はメインモデルが持つ |

## 実装方法

### 方法 1: スクリプトによる自動化（最も安価）

判断が不要な作業（ダウンロード・ファイル検証・文字数カウント等）は Python スクリプトで自動化する。
モデルを消費しないため最も効率的。

```
# 例: 画像品質チェック（既に実装済み）
python tools/check_japanese.py 2026-08-28
python tools/check_draft_length.py 2026-08-28
```

### 方法 2: create_thread によるサブエージェント（低コストモデル指定）

検索結果の評価・画像選択など、軽い判断が必要な作業は `create_thread` で低コストモデルを指定して実行する。

```
# 概念（実際のツール呼び出し）
create_thread(
    prompt="以下のWikimedia検索結果から{entity}の最適な画像を1枚選んでください。
           基準: ①解像度1000px以上 ②講演・会見・イベントの現場写真を優先
           ③大头照は避ける ④ファイルサイズ50KB以上
           結果: 選択したURL + 除外したURLの理由を1行ずつ",
    model="flash",  # 低コストモデル
    thinking="low"
)
```

### 方法 3: multi_tool_use.parallel（並列スクリプト実行）

複数の検索・ダウンロードを並列で実行する。

## コスト目安

| モデル層 | 用途 | 1回あたり想定 |
|----------|------|---------------|
| メインモデル | 執筆・選定・統合・Gate 判定 | 高（記事1本分の執筆等） |
| 低コスト（flash/mini） | 検索結果評価・画像選択・スクリーニング | メインの1/10-1/50 |
| スクリプト（モデル不使用） | ダウンロード・文字数・ファイル検証 | 実質ゼロ |

> **目標**: 全工程のコストのうち、サブエージェント・スクリプトが担く割合を 60% 以上にする（メインモデルの消費を執筆と判断に集中させる）。
