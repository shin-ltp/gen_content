## Entry Criteria: 選題検証パス（2026-08-19 追加）

執筆開始前に、`outline.md` の各話題を一次素材と突き合わせて検証する。スクリプト制作は
事実を素材の本文で裏取りする工程であり、選題の誤りはこの段階で最も発見しやすい。

1. **事実・日付の確認**: 決算・統計・イベントの日付（本日か翌日か）、数値、期待値を一次素材で確認
2. **米国株関連性ゲートの再確認**: 各話題が米国株との内在的な繋がりを持つか（Phase 1 のハードゲートと同じ基準）
3. **鉄則二の原料確認**: 目標株価・レーティング素材の有無。なければ代替トピックへの差し替え or 制約の明示的告知

検証結果の扱い:
- 誤りを検出した場合は `outline.md` を直接修正し、`status.md` の差戻しログに記録する
- 話題自体が関連性ゲートを不通過する場合は、その話題を削除し予備から補充（Phase 1 へ完全差戻しは
  代替候補がない場合のみ）
- 修正は `outline.md`（単一の真実源）に反映し、ドラフト側にのみ反映して放置しない

> 起源: 2026-08-19 の二件。①宇樹科技IPO（美股関連性なし、対比の趣味で主題化）②D表の決算日付
> 誤り（Lowe's/TJX/ADIを木曜扱い）。いずれも執筆時の素材精読で判明した。

## 二層構造の原則（2026-08-19 明確化）

スクリプト制作は **内容層 → 音声層** の2段で行う。Phase 2 は内容層のみ担当する。

1. **内容層（Phase 2 = draft-{A,B,C,D}.md）**: 論理・データ・出所・行動結論の品質に集中して執筆する。
   TTS の読み表記（数字の漢字化・[pause] 等の演出記号）は **書かない**。内容の修正コストが最も低い段階で
   品質を最大化するため。
2. **音声層（production/segment-map.json → tools/tts/）**: Phase 4 検査合格後、完成稿から変換する
   （数字の漢字読み・[pause] 挿入は `tools/tts/prepare_tts.py` が自動処理。音声と映像の同期は
   segment-map の切り分け＋合成後の durations.json が担う）。

> 理由: 内容修正が TTS 変換のやり直しを引き込むと二重コストになる。変換は一方向・一回に限る。

## ドラフトの形式（機械可読な契約・2026-08-28 改訂）

各ドラフトは **ナレーション本文と採用素材表のみ** で構成する。**シーン表は廃止**。
視覚は内容の後に設計する（後述「Phase 3 / 視覚設計への引き渡し」）。

```markdown
## B-1 セクション見出し（上限 12分）
（ナレーション本文。話し言葉として自然な文。数字は算用数字で良い）

## 採用素材
| 素材ID | 用途 |
```

- **シーン表廃止の理由（2026-08-28）**: 旧方式では「1テーマ=5画面」などの頁割りが暗黙の字数上限として働き、
  Phase 1 の時間配分（例: B-1 に 570秒）が Phase 2 の場面表（合計 255秒）で無断変更される事故が起きた。
  内容の長さは内容の価値で決め、視覚の頁数はそれに従属させる。
- **採用素材表**: draft が参照した素材の ID を列挙（`assets_needed` 列は廃止。アセット需要は視覚設計ブリーフで定義）。
  scriptwriter は対応する `collection/` ファイルの frontmatter を `adopted: true` に更新する。

## B テーマの分量管理（2026-08-28 追加）

換算: **1分 ≈ 350字**（暫定値。初回 TTS 合成後に `durations.json` の実測語速で校正する）。

| 項目 | 分 | 字数（350字/分換算） | 判定 |
|------|----|----------------------|------|
| 執筆目標（各テーマ） | 内容に応じ調整 | 分量不足を埋めるための最低字数を設けない | 目標 |
| 警告帯（各テーマ） | 7分未満 | 2,450字未満 | 警告のみ（下限は目安） |
| 硬上限（各テーマ） | 12分超 | 4,200字超 | 不合格 |
| B 合計窓（終選時） | 40分以内 | 分量は内容品質で判断 | 40分超は不合格 |

- 各テーマの執筆後に `tools/check_draft_length.py` で分量を検査する。分量不足のみで不合格にせず、12分超のみ失敗にする（2026-09-11 改訂）。
- **短い場合はまず質点検査**：深度・完全性・因果の明確さが足りるなら拡張しない。不足があるときだけ、証拠の追加／反方の論拠／シナリオ分析／投資判断の方法論で補う。
- **長い場合の削減メニュー**: 最弱の論拠・重複する例示・結論に直接効かない数字を削る
- 過渡語・復述・字数調整のための説明追加は禁止（Gate #2 の密度検査で排除する）
- **執筆順序**: B（候補を執筆）→ 分量検査 → 終選 → A（終選テーマに対応する予告）。C/D は任意のタイミングで並列制作可

## B テーマ終選（Phase 2 完了時・2026-08-28 追加）

- 候補（通常5件・最少4件も可）から **B 合計 40分以内** を目安に組み合わせを選ぶ（採用 3-5 テーマ・N を固定値にしない）。40分超は不合格とし、品質基準を満たすなら短くても採用してよい。
- 落選テーマは情報密度・素材の豊富さが最も低いものから外す（品質で選ぶ。字数調整のための落選はしない）
- 終選結果は `outline.md`（単一の真実源）と draft-B の両方に記録する（各テーマ見出しに 採用/落選＋確定分数）
- A の予告は **終選後の採用テーマ** に対応させる
- **前集との呼応（2026-09-09 追加）**: outline.md に `継続主題承認` があるテーマは、本編の冒頭 1-2 文で
  前集の扱い（前夜の問い・予想・論点）を明示的に受け、当日の新事実がそれに対する反証・補強・深化の
  どれに当たるかを述べてから本題へ入る。前集の数字・発言の再掲は背景 2-3 文以内に限定する。

## Phase 3 / 視覚設計への引き渡し（2026-08-28 改訂）

シーン表は廃止。視覚は文字内容の決定後に設計する。引き渡しは **視覚設計ブリーフ**
（`production/visual-brief.md`）で行う:

1. 2026-09-17 以降、`write_blocks.py` は台本確定と同時に **Slide切分＋`visual-brief.md`＋`visual-data.json`**
   を生成する。B1..Bn の全ページ、A予告、市況、C/D、END系が 1 Slide = 1 segment で対応する。
2. ブリーフは **Slide単位の候補アセット一覧** を持つ。Phase 3 はこれを取得の正式インプットにする。
   B の各Slideは当該ページの主体・数字・論点から素材を選び、2026-09-19以降のA予告は **s1 一覧1枚** で
   B各テーマの `assets/b{n}-1.png` を循環表示する。
3. Stage S2 に相当する `visual-data.json` は write_blocks が既に作る。Phase 3 は取得済み素材の
   実パスをブリーフと visual-data へ反映するだけで、前日 JSON のコピー流用や空参照を残さない。
4. 視覚ページに時間の割当をしない。影音の同期は `tools/tts/` の segment-map（音声の実測時間で駆動）が担う

### 視覚設計ブリーフの定義（シーン表の後継）

テーマごとに以下を記載する。旧シーン表が下流（Phase 3 / Stage S2）へ供給していた情報のうち、
**アセット需要・チャート要求・出所はブリーフが引き継ぐ**。2026-09-17 以降は頁立てを
write_blocks.py のSlide切分が確定し、秒数は segment-map が音声実測で駆動する。

| 項目 | 内容 | 旧シーン表からの引継ぎ |
|------|------|----------------------|
| テーマ核心メッセージ | 1 文で表現 | ―（新設） |
| 可視化候補 | キーコンセプト（構造・仕組み）／キー数字（ヒーロー数値・対比）／引用（発言者付き）／比較対照（peer比較・歴史対照） | 「画面内容」の原料 |
| チャート候補 | [vision-design §0.6](../spec/vision-design.md) の4场景に該当するもののみ `chart:<指標>_<期間>` ＋出所候補 | 「必要アセット」の chart:* 要求 |
| 候補アセット一覧 | Slide行ごとに `theme-image:b{n}-{p}` / `photo:nvidia-hq` / `logo:nvidia` / `person:jim-cramer` 形式で記載する。**Phase 3 取得の正式インプット**（write_blocks.py が自動生成するため手動記載は原則不要） | 「必要アセット」列 |
| 出所マップ | 本文の【出所】と可視化候補・アセットの対応 | 「出所表示」列 |

> A/C/D は固定版式（[vision-design §3](../spec/vision-design.md) の市況カード・ニュース一覧・週間タイムライン）のため、
> ブリーフは「使用データとアセット確認」程度の軽い記載でよい。

## TTS へのインプット契約（内容層の執筆規約）

- ナレーション本文は **そのまま音読して自然な文** で書く（1文60字目安・長文を分割）。
- 数字は算用数字のままで良い（漢字読みへの変換は音声層）。ただし `%`・`〜`・`-` 等の記号に依存した
  文は書かない（音声層で「パーセント」「から」に置換される前提で、文として成立させておく）。
- 見出し・採用素材表・メタ情報は読み上げ対象外。ナレーションは本文段落のみ。
- 「図の通り」等の視覚依存の表現は使わない（音声単体で情報が完結すること）。

## 標準日本語ライティング契約（執筆プロンプトの固定前置文・2026-09-09 改訂）

Phase 2 の各執筆呼び出しでは、コーナー固有の指示の前に **次の前置文を必ず与える**。
処理モードは「素材の翻訳」ではなく **「日本の株式番組向け標準日本語での再構成」** とする。

```text
あなたは日本の証券・資産運用業界で長く実務に携わったベテラン金融アナリストであり、
個人投資家向け株式番組の脚本も手がける専門家です。入力素材は「日本語へ訳す対象」では
ありません。事実を取り出したうえで、日本の投資情報として自然な放送台本を最初から書き
直すための材料として扱ってください。

【基本姿勢】
- まず事実・数字・出所・論点を抽出し、その後に素材の文章から離れて日本語で構成を設計する。
- 素材の語順・見出し・比喩・キャッチコピー・断片文を写さない。段落ごとに「聴き手が
  何を理解できるか」を決めてから書く。
- 中国語素材を語彙単位で置換する作業をしない。日本の金融・投資コミュニケーションで
  定着した標準用語と文体的距離感を使う。
- 原語の概念に定訳がない場合は、専門用語を無理に作らず、短い説明で意味を確定してから進める。

【言語処理】
- 中国語の語彙、語順、慣用句、見出しの発想を日本語に写さない。

【中国語素材の書き換え例】
- 端側AI → オンデバイスAI
- 海峡や輸送の文脈の流量 → 通航量／輸送量
- ネットワーク・アプリの文脈の流量 → トラフィック
- 入門価格 → 買い替えエントリー価格／低価格帯モデルの価格
- 開発株 → 研究開発型銘柄（AI・新薬・素材など、開発の対象を明示）
- 庄家 → 「主導的に買い集める大型投資家」等の説明表現
- マクロ変数日 → マクロ指標の発表日
- ペット株 → ある指標やテーマに沿って分類された銘柄の群れ（例: 指数連動型の投資対象）

【聴取しやすさの設計（2026-09-11 追加）】
- 各論点は「結論 → 最重要の根拠 → 聴き手の判断視点」の順で設計する。細部は2〜3個まで圧縮し、
  それ以上の数字・時系列・機関名は画面に任せる。
- 1文に複数の因果や条件を入れない。長い因果連鎖は短文へ分割する。
- 解説の対象は、一般の投資リスナーがつまずく相対的に専門的な語に限る。身近な金融用語は
  解説せず、解説は1テーマにつき最大1つ。5〜15字の補足を文の流れに組み込み、定義の割り込みで
  議論を断たない。
- 聴いて一度で意味が取れるかを基準にする。権威的な漢語連続・形容詞過多・修辞的な強調で水増し
  しない。難しい事実ほど、具体例か比較で意味を確定してから進める。

【絶対禁止の直訳例】
- 強気相場は「強気相場」「上昇相場」「株高」で表現し、「AI株の強気相場」等と書く。
- 弱気相場は「弱気相場」「下落相場」で表現する。
- 長期債は「長期債」または「長期国債」で表現する。
- 買い方は「買い方」、売り方は「売り方」で表現する。

【リスナーが聴いて意味が分かる表記】
- ナレーションでは英語の会計年度略称を使わない。年度は「2028年度」等の日本語表記で書く。
  企業の年度境界が暦年と異なる場合、初出時に「2028年1月までの会計年度」等を付ける。
- 一般リスナーが意味を取れない内部略語は、初出時に短い日本語説明を付けるか使わない。
- 「+70%」のような記号式ではなく「70%増」と、音読して成立する文にする。
- 見出し・テーブルは内容層の整理用だが、ナレーション化する文は上記と同じ標準形に直す。

【仕上げ】
- 全文を音読前提で読み直し、中国語素材に引きずられた語感、硬い漢語の連続、未説明の略語、
  聴き手が意味を取れない役割語がないことを確認する。
- 日本語として不自然な文は、事実を保ちながら文構成から言い換える。数字や例示の順序を
  組み替えてよいが、出所・時点・因果の関係は変えない。
- 完成後に `python tools/check_japanese.py <date>` を実行し、ERROR をゼロにする。
- WARN が出た項目は文脈を確認する。中国語の発想が残る場合は、その段落を書き直す。
```

この前置文の意図は「見た目の日本語」ではなく **聴いて理解できる日本語** を強制することにある。
素材言語が中国語・英語いずれでも適用し、A/B/C/D の全ナレーションと `outline.md` の予告文に適用する。

## 中国語素材の言語品質ゲート（2026-08-19 追加）

WallstreetCN・36kr 等の中国語素材を参照する場合、以下を厳守する。Gate #2 の検査項目でもある。

1. **簡体字の残留禁止**: ナレーション・採用素材表・視覚設計ブリーフを含め、稿内に簡体字を残さない
2. **直訳の禁止**: 中国語の語彙・語順をそのまま日本語化しない。日本の金融で定着した言い方に置き換える
   （例: PER、非経常損益を除いた純利益、目標株価、個人投資家）
3. **中国企業名は正式英語名称**: 日本語カタカナ・中国語表記ではなく Unitree・Ant Group・DeepSeek・
   Alibaba 等の公式英語名を使う（TTS の読み安定性も確保できる）
4. **出所表示も英語名**: WallstreetCN、36Kr のように媒体名も英語表記で統一
5. **中国語特有の比喩・役割語は日本語圏の等価表現に**: そのまま持ち込むと視聴者に伝わらない
   （例: 「护城河」→「護城河」は日本でも定着しており可、「避税Alpha」等の造語は説明に置き換える）

> 起源: 2026-08-19 draft-B で出所表示に中国語の媒体名が残留し、規範自体にも中国語由来の表記が
> 混入していた。執筆時の機械的変換に頼らず、完成稿に対して簡体字スキャンを必ず実行する。

## 日本語品質ゲート（2026-08-29 拡大・全文字出力対象）

中国語素材に起因しない日本語の誤用も含めて、**すべての文字出力**を機械＋人力で検査する。
対象: `outline.md` / `draft-{A,B,C,D}.md` / `visual-brief.md` / `segment-map.json`（ナレーション） / `visual*.html`（画面文言・注釈含む） / `production/tts/*.txt`（音声直前テキスト）。

1. **機械チェック（必須）**: `python tools/check_japanese.py <date>` が ERROR ゼロで終了すること。
   WARN は中国語直訳の疑いがある語を示す。文脈を人力確認のうえ対応する。
2. **業界用語の日本語標準形（ガイドライン）**: 中国語の金融用語をそのまま持ち込まない。
   - 中国語の「guidance」系訳語 → **ガイダンス／業績見通し**（例「1年先ガイダンス」）
   - revenue → **売上高／収益**（income 意味の漢語は収益認識に使わない）
   - 中国語の「financial report」系訳語 → **決算／決算発表**
   - 中国語の「cybersecurity」略称 → **サイバーセキュリティ**
   - 中国語の「market cap」系訳語 → **時価総額**
   - 中国語の投資銀行略称 → **モルガン・スタンレー**（中国語略称を読みに持ち込まない）
   - bookings → **受注**
   - customer account → **アカウント**（bank account はこの限りではない）
   - seat 単位の課金 → **シート課金**
   - M&A closing → **完了**
   - catalyst → **カタリスト**（株価材料の意では片仮名が一般的）
   - Bull & Bear 指標 → **ブル・アンド・ベア指標**
3. **表現の自然さ（人力）**: 各コーナー読了後に、日本語として不自然な直訳・硬い言い回しを
   読み直して修正する（例: 「史上2位」→「史上2番目」、「crypticな」→「謎めいた」、
   「好決算」→「好調な決算」）。

> 起源: 2026-08-28 の全工程実走で、visual.html をはじめ各出力に中国語直訳語彙が計145箇所混入した。

## 開口・結びの定型（2026-08-19 追加）

## コーナー別の執筆（並列可）

A/B/C/D 各コーナーは [../spec/content-framework.md](../spec/content-framework.md) §3 の方法論に従い執筆する。C/D は並列制作可能。**A は B 終選後に制作する**（予告が終選テーマと一致する必要があるため）。

- **A（オープニング）**: 予告は B 終選の採用テーマ数 N で作る。最初の文は「本日、Nつのテーマを取り上げます。」、列挙後の締めは「今日はこのNつのテーマについてとことん解説いたします。」（省略不可・N一致必須）。2026-09-19以降、各予告は **20字以内短标题＋80字以内简介** で、TTSは `短标题[pause short]简介`。画面は s1 一覧1枚のみでタイトルだけ表示する。2026-09-17 以降の順序は 予告 → 市況総括とし、市況総括は当日 `collection/MKT-*.md` の決定的要因（金利・暗号資産・セクター等）を方向・数値・理由まで説明する（[content-framework.md A-p(N+1)](../spec/content-framework.md)）。俳句は2026-09-17廃止。
- **B（メインテーマ・核心）**: 候補（通常5件・最少4件も可）を執筆（「昨日注目セクター・個別株深層分析」を必ず含む）→ 分量検査 → **B 合計 40分以内で終選（採用3-5テーマ）** → 各テーマの最後に行動結論（鉄則二）。
- **C（News Highlights）**: 8本、各30字以内、タイトル中心。**視覚は8本を1枚の一覧カードに表示**し、読み上げに同期してハイライトを切替える（1本ずつの詳細スライドは作らない）。**一覧画面は画像不使用**（画像検索・生成画像・ロゴ・サムネイルなし・2026-08-31 改訂）。読み上げはタイトル＋簡潔な要約。
- **D（直近イベント予告）**: DB `economic_calendar` から直近3営業日の重要イベント。該当なければスキップ。**視覚は週間タイムライン1画面のみ**（1日ずつの詳細スライドは作らない）。

> 個別株/セクターを扱う場合、鉄則二（大手目標株価＋アクション価格＋ポジション目安）を必ず示す。出力形式は [../spec/valuation.md](../spec/valuation.md)。バリュエーション手法は業界別に使い分け（[../data-sources/sector-valuation-guide.md](../data-sources/sector-valuation-guide.md)）。
