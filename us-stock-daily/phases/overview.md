# 制作ワークフロー概観（Phase 0〜5）

> 旧 PLAN.md 第二章。制作は単一エージェントへの丸投げではなく、**Phase 0〜5 の多段階ワークフロー**で進行する。
> 各 Phase の詳細仕様は同ディレクトリの各ファイル参照。マスター計画は [../PLAN.md](../PLAN.md)。

---

## 設計思想

かつての設計では制作要件が1ファイルに集中し、単一エージェントが全工程を担当すると「手抜き」が発生しやすかった。本設計は以下の原則でこれを解決する：

1. **工程の分割（Phase 化）** — 制作を直列／並列可能なフェーズに切り分け、各フェーズを独立したサブエージェントが担当する。
2. **責任の局所化** — 各エージェントは「自分の Phase の入出力と品質ゲート」だけに集中する。全体構成判断はスケジューラ（PLAN）と後段フェーズが担う。
3. **成果物の永続化** — 各フェーズの成果物は必ずディスクに保存する（メモリ受け渡し禁止）。後段エージェントは常に最新の確定成果物を読める。
4. **段階的品質ゲート（Staged Checks）** — フェーズ完了ごとに検査を通過しない限り次フェーズに進まない。手抜きを構造的に防ぐ。
5. **遅延取得（Lazy Fetch）** — 重い処理（画像・チャートのクロール等）は必要になった瞬間にだけ実行する（Phase 3）。

## タスクスケジューリングと依存関係（DAG）

```
[Phase 0: 情報収集]
        │  （品質ゲート#0 通過で確定）
        ▼
[Phase 1: テーマ選定・構成]
        │  （品質ゲート#1 通過で確定）
        ▼
[Phase 2: スクリプト制作] ──B終選（25-40分窓）──▶ [視覚設計ブリーフ] ──▶ [Phase 3: 視覚素材取得]
        │                                                        │
        │  （品質ゲート#2）                                       │ （品質ゲート#3）
        ▼                                                        ▼
[Phase 4: 品質検査] ◀────────────────────────────────────────────┘
        │  （品質ゲート#4：不合格なら Phase 2 へ差戻し）
        ▼
[Phase 5: 統合・最終化]  → 完成スクリプト ＋ 俳句OP ＋ 免責
```

- Phase 0→1→2 は厳密に直列（前段の確定成果物が入力）。
- Phase 2 完了時の B テーマ終選（合計 25-40 分窓）後に視覚設計ブリーフを作成し、Phase 3 が起動する
  （2026-08-28 改訂。旧「Phase 2 と並行のインクリメンタル取得」は廃止）。
- Phase 4 は Phase 2・3 の両方が一段落してから実行。不合格項目は Phase 2（必要なら 3）へ差戻し。

## 段階的品質ゲート（Staged Checks）

各 Phase に **Entry Criteria（開始条件）／ Definition of Done（完了定義）／ Gate Check（検査）** を定義する。Gate を通過しない限り次 Phase に進まず、`status.md` に結果を記録する。

| Gate | 対象 Phase | 検査の概要 | 合格で進む先 |
|------|-----------|-----------|--------------|
| #0 | 情報収集 | カバレッジ・定量・URL/本文完備・網羅性・重複・索引完全性・DB鮮度（詳細は Phase 0）。`collect-all.mjs` が自動評価し、不合格は exit 2 で Phase 1 をブロック | Phase 1 |
| #1 | テーマ選定 | 選題原則の採点記録／B候補5テーマ（素材容量ゲート通過）／B核心割当／サスペンスフック／直近イベント要否 | Phase 2 |
| #2 | スクリプト | データ密度・情報源・アクション指針（鉄則二）・独立性・分量（各7-12分／B合計25-40分で終選）等 | Phase 4（Phase 3 は終選後ブリーフ経由で起動） |
| #3 | 視覚素材 | 採用素材の必要画像漏れなく取得／ロゴは brands キャッシュまたは新規取得で揃う | Phase 4 |
| #4 | 品質検査 | 多視点チェックリスト（不合格→Phase 2 差戻し） | Phase 5 |

> 各 Gate の検査基準の詳細は対応 Phase ファイルおよび [phase4-qa.md](./phase4-qa.md) のチェックリストを参照。

## 日次ワークスペースとステータス管理

1日＝1ディレクトリ。全 Phase の成果物を同じディレクトリに集約し、進行状況を `status.md` で一元管理する。

```
daily-output/YYYY-MM-DD/                 # ★ 1日分のワークスペース
├── status.md                            # 当日の Phase 進行ステータス・品質ゲート結果
├── YYYY-MM-DD.md                        # Phase 5 の最終完成スクリプト
├── collection/                          # Phase 0 成果物（詳細は Phase 0）
├── assets/                              # Phase 3 の遅延取得画像等
├── production/                          # Phase 1〜2 の中間成果物
└── review/                              # Phase 4 の品質ゲート検査レポート
```
