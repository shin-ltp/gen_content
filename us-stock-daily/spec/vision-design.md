## 0. グローバルデザインシステム（共通基盤）

### 0.1 基礎画面仕様

| パラメータ | 仕様 |
|-----------|------|
| 解像度 | **1920×1080**（16:9）。縮小配信時もこの比率を維持 |
| 番組名 | 角ヘッダーは**【Smart Assets 米国株】**、正式チャンネル名は**【Smart Assets 米国株投資チャンネル】**。参考番組名（美投・美投侃新聞）は画面へ出さない |
| 人物出演 | **なし**（純図文＋ナレーションのPPTスライドスタイル） |
| 字幕 | 下部エリアに日本語字幕（白色フォント・ナレーションと同期） |
| 署名 | 個人見解は本文内ラベル（「当番組の見解」等）で明示。**画面フッター行・右下署名行は設けない**（2026-08-27 改訂） |
| 全体基調 | 美投侃新聞のデザインを規範とする（高級感・情報密度重視・出演コストゼロ） |

> **共通ヘッダー（2026-08-27 改訂）**: 各画面の角ヘッダー（**ロゴ＋Smart Assets 米国株**）は**右下に統一配置**する（テーマ見出しとの混雑を避けるため右上には置かない。オープニングタイトルカードを除く）。日付チップ・コーナー名チップなどのページラベルは**表示しない**。A-1 / B-2 / C 等の**テンプレ構成名を画面に出さない**（編集上の小見出し「発端」「歴史比較」等は可）。**画面フッター行（出所・注釈・ページ番号）は設けない**。
>
> **出所表示（2026-09-03 改訂）**: 出所は**画像・チャートの左下部キャプションのみ**に表示し、本文・データカード・注釈列には出所行を設けない。**当番組自作のテーマ画像・図は出所キャプションを表示しない**。外部取得の写真・人物写真・チャートは取得元を出所に明記する。**WallstreetCN 等の中国語ソースは画像・チャートの場合も含めて一律非表示**とする。
>
> **B テーマ見出し（2026-08-28 改訂）**: B セクションは 1 テーマを複数画面で展開するため、**テーマ見出しチップ**（例: `テーマ①｜長期金利と半導体急落`）を表示し、今どのテーマの話かを常時示す。チップは**画面最上部のヘッダー行に固定**し、**本文列の左端に揃える**（左図右文ページでは右コンテンツ列の左端）。上下中央配置の対象は**小見出し→タイトル→本文のみ**（チップを含めない）。**中央配置の計算領域はヘッダー行の下端（約110px）から下部ロゴ帯まで**とし、ヘッダー行の高さを含めない（内容が多いページでチップと本文が重ならないようにする）。小見出し→タイトル→本文の間隔は固定とし、タイトル直下の空白が日によって膨らまないよう本文側の独自中央寄せはしない。
>
> **オープニングタイトルカード＝YouTubeサムネイル（2026-08-28 改訂）**: S0 は YouTube のサムネイルを兼ねる。**大型ロゴ＋チャンネル名（Smart Assets 米国株投資チャンネル）＋メインタイトルを横並びのロックアップ**（ロゴは左端、チャンネル名はタイトル直上）で画面中央に配置し、角ヘッダーは置かない。タグライン等の補足は付けず、**モバイルの一覧表示でも読める文字サイズと高コントラスト**を最優先する。
>
> **S0 固定背景（2026-09-18 改訂）**: S0 の背景画像は**全エピソード共通で `assets/opening.png`（ウォール街の夜景＋赤緑 K 線光軌）**に固定する。日次のテーマ画像を S0 背景に流用しない。Phase 3 は [`assets/brands/template/opening-visual.png`](../assets/brands/template/opening-visual.png)（ソーステンプレート）を当該回の `assets/opening.png` へコピーし、visual.html は `<img src="assets/opening.png">` で参照する。

### 0.2 2系統のビジュアルスタイル

コンテンツタイプに応じて切り替える。これが画面の「温度」を決める。

| スタイル | 適用シーン | 背景色 | 文字色 | 対応コーナー |
|---------|----------|--------|--------|--------------|
| **明るいニュース風** | 速報・一覧・予告 | オフホワイト／ライトクリーム | ダークカラー地＋赤緑の騰落色 | A・C・D |
| **ブラックボード深層分析風** | 深掘り解説・個人見解・結論 | 濃紺 または 深緑 | 明るい黄色の見出し＋白色の本文 | B |

### 0.3 カラーシステム（セマンティック色）

色は「役割」で定義し、一貫して運用することで視聴者に条件反射を形成する。

| 役割 | 色 | HEX（目安） | 使用シーン |
|------|----|------------|-----------|
| キー数字・警告・下落 | 赤 | `#D32F2F` | 核心的バリュエーションデータ・目標株価・下落数字・リスクシグナル |
| 情報源・上昇 | 緑 | `#2E7D32` | 出所表示・市場上昇数字 |
| 強調・見出し | 黄（蛍光ペン効果） | `#FBC02D` | メイン論点・重点テキスト |
| 本文・字幕 | 白 | `#FFFFFF` | 本文リスト・下部字幕 |
| 背景（深層分析） | 濃紺／深緑 | `#0A1628`／`#0F3D2E` | ブラックボード系背景 |
| 背景（ニュース） | オフホワイト／クリーム | `#FAF6EE` | 明るいニュース風背景 |
| 強調アクセント | 金 | `#D4AF37` | 特別枠・装飾（俳句廃止に伴い汎用化） |
| 分類ブロック | ライトグリーン／ライトピンク | `#E8F5E9`／`#FCE4EC` | 騰値上位（緑）vs 下落上位（ピンク）の色ブロック分類 |

### 0.5 画面レイアウトグリッド（モジュラー・3層構造）

```
┌───────────────────────────────────────────┐
│ 上部: 右上ロゴ＋番組名／メインタイトルは本文側       │
├─────────────────┬─────────────────────────┤
│  左: 配図（画面高100%・余白なし）                  │
│  ／テーマ画像        │  メインタイトル／小見出し       │
│  出所は画像内    │  核心データリスト           │
│  下部に表示      │  （赤=キー数字／白=説明）    │
│   (40%)         │              (60%)        │
├─────────────────┴─────────────────────────┤
│ 下部: フッター行なし（字幕は動画編集で別途合成）    │
└───────────────────────────────────────────┘
```

**2つの構図パターン**（コーナーで使い分け）：
- **左図右文式**（深層分析 B 等）：左40%の画像は**画面高100%・左余白なし**で全面配置し、出所は画像内下部キャプションに表示。右60%にタイトルとテキスト論述。**フッター行は設けない**。
- **全画面カード式**（市場速報・ニュース C 等）：3層の並列モジュールで一覧表示。

### 0.6 チャート条件付き使用ルール（2026-08-28 改訂）

伝統的なチャート（ローソク足・折れ線・棒グラフ）は**既定では使わない**。ただし、以下の **4场景でのみチャートの使用を許可**する:

| # | チャート使用场景 | 例 |
|---|----------------|-----|
| 1 | **長期トレンドの提示** | 30年債利回りが19年ぶり高値に至る軌跡／SOX 指数の年初来推移 |
| 2 | **周期性・規則性の可視化** | 金利サイクルと株価パフォーマンスの周期／セクター・ローテーションの反復 |
| 3 | **歴史イベントとの対照** | 5大バブルのピーク局面の重ね合わせ／過去の利上げ局面との比較 |
| 4 | **複数指数・指標の相互作用分析** | 長期金利×半導体株の逆相関／ドル円×輸入インフレの連動 |

**チャート使用時の鉄則**:

- 軸・期間・単位・外部出所を必ず明記。出所は左画像内の下部キャプションに表示（§0.5 共通ルール準拠）。当番組自作チャートは出所キャプション不要、中国語ソース由来は出所非表示
- **1画面1メッセージ**。チャートが示す結論を右コンテンツのテキストで近接提示し、「何を言いたい図か」が一目で分かるようにする
- 1920×1080 に引き伸ばして鮮明な高解像度素材のみ（SVG または高解像度 PNG）
- 系列は原則 **2〜3本まで**。モバイル視認性を損なう密集図・多系列図は使わない

**純数字＋色ブロック＋段階リストを優先する场景**（チャートにしない）:

| # | 優先场景 | 表現方法 |
|---|---------|---------|
| 1 | 単一スナップショット値（本日の指数・騰落率・時価総額） | **純数字＋色コーディング**（例 `S&P -0.28%`（赤）） |
| 2 | 単純比較・順位（値上がり/値下がり筆頭、KPI 並列） | **色ブロック分類**（ライトグリーン=騰値上位、ライトピンク=下落上位） |
| 3 | 因果・論理の段階展開（割引率メカニズム等の説明） | **論理的段階リスト**（現状→成長率→予測→バリュエーション導出） |
| 4 | 分類・構造の提示（デュオカード、セクター分類） | **色ブロック＋小ロゴ**、テーマ画像 |
| 5 | 短期変動・粒度が細かすぎるデータ | チャート化せず結論を直接陳述（**テキスト化データ**: 「過去に何度も80%超の下落」） |
| 6 | 象徴的に示せるもの | **象徴的配図**（ブランド実写・テーマ画像でデータを代替） |

> **データ取得**: Phase 0 では従来どおりチャートを収集しない（記事内チャートはフラグのみ）。**視覚設計ブリーフでチャートが必要と判定された场景**に対し、**Phase 3 が能動的に検索・収集**する（履歴データ: Stooq／FRED／Yahoo Finance、既製チャート: 公式 IR・信頼できる金融メディアの高解像度スクリーンショット）。詳細は [../phases/phase3-asset-fetching.md](../phases/phase3-asset-fetching.md)。ロゴ・実写は引き続き共有キャッシュ [../assets/brands/](../assets/brands/) 優先。

### 0.7 共通アニメーション語彙とテンポ

| 効果 | 用途 | テンポ目安 |
|------|------|-----------|
| フェードイン | 見出しの登場 | 緩やか（結論） |
| スライドイン | リスト項目の逐次表示 | 中速（データリスト） |
| ハイライト強調 | 話中のテーマ/ニュースの注目 | 即時（話題と同期） |
| スタイル切替（暗→明＋赤） | コーナー転換のアンカー | 切替点で1回 |

画面持続時間の目安：高密度カード 60-90秒／解説スライド 15-30秒／結論 10-20秒。

### 0.8 画像レイアウトと使い分け（2026-09-09 人物写真判定 改訂版）

**三つのレイアウトパターン**（参照例に基づく・2026-08-31 確定）:

| パターン | レイアウト | 使う場面 | 参照例 |
|---|---|---|---|
| **A. 話題を示す人物実写** | **左40% 全高の縦位置写真** + 右60% コンテンツ。標準 split | ニュース配図、講演、会見、イベント写真 | 図1（ウォッシュ講台） |
| **B. 人物のプロフィール表示** | **円形ヘッドショット（320-400px）を左側垂直中央**、円内下部に氏名、右に見解・論点 | アナリスト評価、エコノミスト主張、官僚・CEO の portrait 表示 | 図2（ウォッシュ円形） |
| **C. テーマ画像・経済データ** | **左40% 全高** テーマ画像/実景 + 右60% データ。split | 経済指標、行業、技術トレンド | 図3-5 |

> **重要**: 人物写真はまず「その話題・場面を示す実写か、プロフィール写真か」を判定する。判定は画面種別（引用・解説など）で行わない。話題実写は split、プロフィール写真は円形。円形を「見解引用専用」に限定しない。

**人物写真の優先順と版式（2026-09-09 確定）**:

| 優先 | 採用する素材 | 版式 |
|---|---|---|
| 1 | **そのニュースの配図**（人物の発言シーン・会見・現場写真を含む） | **split 全幅** |
| 2 | **他の場面での講演・発言写真**（当該ニュース写真が取得できない場合） | **split 全幅** |
| 3 | **発言・頭部が鮮明な高解像度写真** | 上2種で適切な横長・全高写真にできない場合のみ split |
| 4 | **プロフィール写真・公式ポートレート**（上3種が取得できないか、素材が本来 portrait の場合） | **円形・左側垂直中央** |
>
> **B 版式の実装制約**: class は `slide profile` を使い、円形アバター＋氏名の列を**必ず `<div class="visual">` で包む**こと。`photo-frame` 内に `<img>` と `.pf-name` を置く。テンプレート CSS では `.slide.profile` にも `.chrome` と `.theme-chip` の左オフセットを適用済みであり、この規則を削除・個別上書きしない。2026-09-09 の s18〜s20 は、profile 版式のみ左オフセットが定義から漏れて文字が画像下へ崩れた再発例である。

| 表示コンテキスト | 使う画像（優先順） | 効果 | 主な適用先 |
|---|---|---|---|
| **人物の話題実写** | ① 当該ニュース添付・発言シーン → ② 他の場面の講演・会見 → ③ SearXNG「{氏名} speech」 | 誰が何を語っているか文脈ごと伝わる | **A（split 全高）** |
| **人物のProfile** | ① 発言・頭部が鮮明な高解像度写真 → ② 公式ポートレート → ③ Wikipedia | 「この人がこう言った」が即座に伝わる | **B（円形・垂直中央）** |
| **企業・機関の単独表示** | ① **社名・機関名が写り込む本社・代表的な建築物の高解像度実写** → ② 店舗・工場・施設の実写 → ③ Wikipedia インフォボックス → ④ SearXNG | リアリティ・説得力 | §4 B の個別株・機関 |
| **物理的オブジェクト**（半導体、DC、ロケット、小売店頭等） | ① **公式IR・ニュース記事の添付写真** → ② Wikipedia/Wikimedia Commons → ③ SearXNG 画像検索 → ④ なければ**生成**（但し実物に寄せる） | 具体性・情報量 | §4 B の技術・施設・製品説明 |
| **政府・中央銀行・財務省** | ① **機関の公式建築写真**（Eccles Building、Treasury Building等）→ ② **関係者の公式ポートレート** → ③ 議会・会見の報道写真 → ④ SearXNG | 権威・実在感 | §4 B の政策・マクロ |
| **アプリ・サービス画面** | ① **公式スクリーンショット**（App Store・Google Play・IR資料）→ ② 報道記事のスクリーンショット → ③ 自身で撮影した画面キャプチャ | 製品の実感 | §4 B の個別サービス解説 |
| **多品牌列挙**（一覧・比較・出所羅列） | 小さなロゴ（背景透過）を**補助的に**配置。可能な限り背景に薄い実写写真や質感のある色面を敷き、ロゴ単体でのっぺりさせない | 視認性＋統一感＋質感 | §2 目玉予告・§5 ニュース速報・セクター一覧 |
| **経済データ・業界テーマ** | テーマに応じたテーマ画像（下記スタイルガイド）または実景写真 | テーマの視覚的アンカー | **C（split 全高）** |

> **鉄則（2026-08-31 最終版）**:
> 1. **人物写真は素材種別で split/円形を判定** — ニュース配図・講演・会見などの実写は split（左全高）。プロフィール写真は円形（参照図1・2）
> 2. **プロフィール写真は一律円形・左側垂直中央** — 引用・解説・政策説明など画面種別を問わず `slide profile` を使う（2026-09-09 s18/s19/s20 再発防止）
> 3. **経済データ・業界テーマはテーマ画像 + split** — 主体が具体的な企業でない場合でも、まず実写写真の画像検索を優先し、得られない場合のみテーマ画像を生成する（参照図3-5）
> 4. **テーマ画像のスタイル**: フラット/ベクター插画で具体的な物件に焦点。3Dレンダー・抽象的比喩は使わない
> 5. **同一画像の多用禁止・段落主体ローテーション（2026-09-18 改訂）** — B テーマ画像（`assets/b{n}-{p}.png`）はページ単位で管理する。p1 は記事全体を基準に取得し、p2..p8 は対応段落を基準に判定する。**段落の行動主体がテーマ主体から逸脱しない限り p1 のファイルを再利用**し（この再利用のみ契約上の例外とする）、**主体が逸脱した段落だけ新規キーワードで検索・生成**する。テーマ間でも内容キーワードを変えてローテーションする。
> 6. **ニュース記事の添付写真があれば最優先**
> 7. **ロゴは補助**
> 8. **ロゴの地色コントラスト** — 透過ロゴを写真枠に収める際、`background` をロゴの本体色と同系にしない（白抜きロゴ＋白背景は不可）。判別不能な場合はロゴを地色に合う色へ加工するか、**社名入りの本社実写写真に差し替える**（§0.8 企業単独表示の優先順に従う）。2026-08-28 s29（白抜き Salesforce ロゴ×白背景）を再発防止例とする
>
> 実写写真・報道写真の取得は [../phases/phase3-asset-fetching.md](../phases/phase3-asset-fetching.md) の取得フローに従う（公式ニュースルーム → Wikipedia → SearXNG 画像検索）。

#### Top slide・ページ画像の運用と素材採用の確定ルール（2026-09-08 新設）

**構成ルール**:

- **B セクション各テーマ = Top slide 1枚 + 分頁画像n枚**。テーマ先頭ページ（`B*-p1`）に使うメイン画像を「Top slide」と呼ぶ。
- **A 予告（2026-09-19以降）**: 一覧ページは **s1 の1枚のみ**。左側に各テーマの短标题だけを表示し、简介は画面に表示しない。右側の画像は**各 B テーマのテーマ画像（`assets/b{n}-1.png`）を巡回・ハイライト使用**する。テーマごとにロゴや追加画像を別途新規作成しない。**新品発表・イベント主題**: テーマ画像は人物ポートレートではなく**製品写真・会場写真を優先**する（Apple 発表なら折りたたみ機本体・ステージ会場。人物は発言の主語がその人物そのものの場合のみ）。
- **B の 2 ページ目以降（2026-09-18 改訂）**: 基本は **p1 のテーマ画像を再利用**する。対応段落の行動主体（人物・企業・製品・機関・標的）がテーマ主体から逸脱した場合にのみ、その段落を基準に新しいページ画像を検索・生成する。判定は prepare_visual_assets.py が段落本文とテーマ全文の比較で行う。

**主体別の画像指定**:

| 話題の主体 | 採用する画像（優先順） |
|---|---|
| 財務省・FRB・政府高官の発言 | ① 官僚の講演・会見写真 → ② 機関の庁舎写真（Eccles Building 等） |
| 投資銀行・銀行の見解 | ① 当該ニュースのアナリスト発言写真 → ② 他の場面の講演写真 → ③ 発言・頭部が鮮明な高解像度写真 → ④ **アナリストのプロフィール写真（円形）**。機関そのものが主体の場合は社名が視認できる建物実写写真 |
| 上場企業（創業者の発言） | **創業者の講演・発言写真**（最優先） |
| 上場企業（非創業者の発言） | 社名が視認できる建物実写写真 |
| **新品発表・イベント主題**（発表会・決算会見等） | **① 当該発表の製品写真・会場写真 → ② ニュース記事の配図 → ③ 公式ニュースルーム素材**。Top slide では関係者のポートレート単独を主役にしない |
| 上場企業（分頁の製品・サービス内容） | 内容に連動した素材：アプリアイコン入り高品質画像・主要プロダクトのロゴ入り画面スクリーンショット等 |
| 指数・ETF・国債など個別標的 | **名称が確認できる高品質画像** |

**採用原則（検索と生成の棲み分け）**:

1. 実物・実在機関・実在人物が存在する題材は**必ず画像検索の結果を素材に採用**し、生成画像は使わない。
2. 高品質な画像が見つからない場合は、**キーワードを調整して再検索**する（例: `{氏名} speech`、`{社名} headquarters`、`{製品} app`）。複数回の再検索でも高品質素材が得られない場合にのみ、**最終手段として生成を検討**する。
3. 市場の動き・センチメント・マクロ指標の変化など、対応する実体・人物が存在しない題材に限り、**生成画像を許可**する。

**キーワード優先順位（2026-09-18・prepare_visual_assets.py と同一契約）**:

1. **新製品発表** → 製品写真 → 製品発表会・会場写真。**講話・声明などニュース事件**は当該記事の配図原图を最優先
2. **行動主体**（企業・経営者・FRB・大統領/政府高官・政府機関・投資銀行・アナリスト・新製品）→ 企業・機関は**社名・機関名が鮮明に写る建物高解像度写真**。人物は**アナリスト見解の引用のみ肖像（portrait）**、それ以外の人物は現場・講演・会見の高解像度写真
3. **抽象主体**（市場走势・心理・価格変動・マクロデータ等の具体実体なし）→ キーワードで**生成テーマ画像**

①②はキーワードで画像検索し、検索後の選図は LLM が「高品質（高解像度・サムネイルでない・ぼやけない）かつ主題に合致」を基準に候補を再ランキングする。③は生成のみ。採用画像は `assets/image-meta.json` に **portrait（人物肖像）フラグ**を記録し、**肖像は左側円形・上下中央、それ以外は左側全高**で表示する（A 予告の p1 画像も同じ規則に従う）。

#### テーマ画像のスタイルガイド（2026-08-31 新設・2026-09-18 用語整理）

**禁止**: 抽象的な3Dレンダー（「黄金の要塞」「クリスタルの柱」等の比喩的表現）。

| テーマ種別 | スタイル | 具体的な描写対象 | 参照 |
|---|---|---|---|
| 雇用・労働 | 写実オフィス/作業現場の実景 | 会議、工場、小売店頭 | 図3 |
| 半導体・HW | フラットベクター插画 | ゲーミング端末、サーバー、基板 | 図4 |
| SaaS・SW | フラット插画 + UI要素 | クラウド、アプリ画面、データフロー | 図5 |
| 金融・マクロ | 実景写真 or 建物 | 取引フロア、政府建築 | — |
| 小売・消費 | 実景写真 | モール、店舗棚 | — |
| エネルギー | 実景写真 | 製油所、風力、太陽光 | — |

**プロンプト5原則**: ①主体キーワードを特定 ②抽象的比喩を禁止 ③具体的な物件を描写 ④配色はテーマに合わせる ⑤`flat vector illustration` / `editorial photo` — `photorealistic 3D render` 禁止

> **生成の責務**: テーマ画像の生成は Phase 3（asset-fetcher、tools/imagegen 使用）が担当する。
> 2026-09-17 以降、Stage S2 相当の `visual-data.json` は write_blocks.py が作成し、
> Phase 3 は完成済み素材の実パスを反映する（[phase3-asset-fetching.md](../phases/phase3-asset-fetching.md)）。
