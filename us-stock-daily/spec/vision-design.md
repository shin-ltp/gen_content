# 視覚デザイン仕様（Vision Design）

> 番組の**視覚表示テンプレート**の定義。全体の色・画面レイアウト・アニメーション効果・画像スタイルを規定する。
> 内容（何を話すか）は [content-framework.md](./content-framework.md)。本章は**それをどう見せるか**。
> **本仕様の §1〜§7 は [../templates/daily-template.md](../templates/daily-template.md) の各部と1対1に対応する。**
> ベースラインの視覚方法論は [BENCHMARK_ANALYSIS.md](../BENCHMARK_ANALYSIS.md) 第七章を参照。

## 0. グローバルデザインシステム（共通基盤）

### 0.1 基礎画面仕様

| パラメータ | 仕様 |
|-----------|------|
| 解像度 | **1920×1080**（16:9）。縮小配信時もこの比率を維持 |
| 番組名 | 角ヘッダーは**【Smart Assets 米国株】**、正式チャンネル名は**【Smart Assets 米国株投資チャンネル】**。参考番組名（美投・美投侃新聞）は画面へ出さない |
| 人物出演 | **なし**（純図文＋ナレーションのPPTスライドスタイル） |
| 字幕 | 下部エリアに日本語字幕（白色フォント・ナレーションと同期） |
| 署名 | 個人見解は本文内ラベル（「当番組の見解」等）で明示。**画面フッター行・右下署名行は設けない**（2026-08-27 改訂） |
| 全体基調 | 美投侃新聞のデザインを規範とする（高級感・情報密度重視・出演コストゼロ） |

> **共通ヘッダー（2026-08-27 改訂）**: 各画面の角ヘッダー（**ロゴ＋Smart Assets 米国株**）は**右下に統一配置**する（テーマ見出しとの混雑を避けるため右上には置かない。オープニングタイトルカードを除く）。日付チップ・コーナー名チップなどのページラベルは**表示しない**。A-1 / B-2 / C 等の**テンプレ構成名を画面に出さない**（編集上の小見出し「発端」「歴史比較」等は可）。**画面フッター行（出所・注釈・ページ番号）は設けず、出所は左画像内の下部キャプション**として表示する。
>
> **B テーマ見出し（2026-08-28 改訂）**: B セクションは 1 テーマを複数画面で展開するため、**テーマ見出しチップ**（例: `テーマ①｜長期金利と半導体急落`）を表示し、今どのテーマの話かを常時示す。チップは**画面最上部のヘッダー行に固定**し、**本文列の左端に揃える**（左図右文ページでは右コンテンツ列の左端）。上下中央配置の対象は**小見出し→タイトル→本文のみ**（チップを含めない）。**中央配置の計算領域はヘッダー行の下端（約110px）から下部ロゴ帯まで**とし、ヘッダー行の高さを含めない（内容が多いページでチップと本文が重ならないようにする）。小見出し→タイトル→本文の間隔は固定とし、タイトル直下の空白が日によって膨らまないよう本文側の独自中央寄せはしない。
>
> **オープニングタイトルカード＝YouTubeサムネイル（2026-08-28 改訂）**: S0 は YouTube のサムネイルを兼ねる。**大型ロゴ＋チャンネル名（Smart Assets 米国株投資チャンネル）＋メインタイトルを横並びのロックアップ**（ロゴは左端、チャンネル名はタイトル直上）で画面中央に配置し、角ヘッダーは置かない。タグライン等の補足は付けず、**モバイルの一覧表示でも読める文字サイズと高コントラスト**を最優先する。

### 0.2 2系統のビジュアルスタイル

コンテンツタイプに応じて切り替える。これが画面の「温度」を決める。

| スタイル | 適用シーン | 背景色 | 文字色 | 対応コーナー |
|---------|----------|--------|--------|--------------|
| **明るいニュース風** | 速報・一覧・予告 | オフホワイト／ライトクリーム | ダークカラー地＋赤緑の騰落色 | A.②/③・C・D |
| **ブラックボード深層分析風** | 深掘り解説・個人見解・結論 | 濃紺 または 深緑 | 明るい黄色の見出し＋白色の本文 | A.①(俳句)・B |

### 0.3 カラーシステム（セマンティック色）

色は「役割」で定義し、一貫して運用することで視聴者に条件反射を形成する。

| 役割 | 色 | HEX（目安） | 使用シーン |
|------|----|------------|-----------|
| キー数字・警告・下落 | 赤 | `#D32F2F` | 核心的バリュエーションデータ・目標株価・下落数字・リスクシグナル |
| 情報源・上昇 | 緑 | `#2E7D32` | 出所表示・市場上昇数字 |
| 強調・見出し | 黄（蛍光ペン効果） | `#FBC02D` | メイン論点・重点テキスト |
| 本文・字幕 | 白 | `#FFFFFF` | 本文リスト・下部字幕 |
| 背景（深層分析） | 濃紺／深緑 | `#0A1628`／`#0F3D2E` | ブラックボード系背景 |
| 背景（ニュース） | オフホワイト／クリーム | `#FAF6EE` | 明るいニュース風背景 |
| 俳句アクセント | 金 | `#D4AF37` | 俳句の文字・装飾 |
| 分類ブロック | ライトグリーン／ライトピンク | `#E8F5E9`／`#FCE4EC` | 騰値上位（緑）vs 下落上位（ピンク）の色ブロック分類 |

### 0.4 タイポグラフィ

| 用途 | 書体 | 備考 |
|------|------|------|
| 本文・見出し | ゴシック系（Noto Sans JP／游ゴシック） | 太字で階層表現 |
| 俳句 | **行書／明朝**（Noto Serif JP／游明朝／行書体） | 高級感・和の趣 |
| 数値・データ | 等幅（タブラー）フォント | 桁揃え・視認性 |
| バイリンガル | 日本語＋英語原文併記（「S&P 500／標普」形式） | 専門用語保持 |

### 0.5 画面レイアウトグリッド（モジュラー・3層構造）

```
┌───────────────────────────────────────────┐
│ 上部: 右上ロゴ＋番組名／メインタイトルは本文側       │
├─────────────────┬─────────────────────────┤
│  左: 配図（画面高100%・余白なし）                  │
│  ／概念図        │  メインタイトル／小見出し       │
│  出所は画像内    │  核心データリスト           │
│  下部に表示      │  （赤=キー数字／白=説明）    │
│   (40%)         │              (60%)        │
├─────────────────┴─────────────────────────┤
│ 下部: フッター行なし（字幕は動画編集で別途合成）    │
└───────────────────────────────────────────┘
```

**2つの構図パターン**（コーナーで使い分け）：
- **左図右文式**（深層分析 B 等）：左40%の画像は**画面高100%・左余白なし**で全面配置し、出所は画像内下部キャプションに表示。右60%にタイトルとテキスト論述。**フッター行は設けない**。
- **全画面カード式**（市場速報・ニュース C 等）：3層の並列モジュールで一覧表示。

### 0.6 チャート条件付き使用ルール（2026-08-28 改訂）

伝統的なチャート（ローソク足・折れ線・棒グラフ）は**既定では使わない**。ただし、以下の **4场景でのみチャートの使用を許可**する:

| # | チャート使用场景 | 例 |
|---|----------------|-----|
| 1 | **長期トレンドの提示** | 30年債利回りが19年ぶり高値に至る軌跡／SOX 指数の年初来推移 |
| 2 | **周期性・規則性の可視化** | 金利サイクルと株価パフォーマンスの周期／セクター・ローテーションの反復 |
| 3 | **歴史イベントとの対照** | 5大バブルのピーク局面の重ね合わせ／過去の利上げ局面との比較 |
| 4 | **複数指数・指標の相互作用分析** | 長期金利×半導体株の逆相関／ドル円×輸入インフレの連動 |

**チャート使用時の鉄則**:

- 軸・期間・単位・出所を必ず明記。出所は左画像内の下部キャプションに表示（§0.5 共通ルール準拠）
- **1画面1メッセージ**。チャートが示す結論を右コンテンツのテキストで近接提示し、「何を言いたい図か」が一目で分かるようにする
- 1920×1080 に引き伸ばして鮮明な高解像度素材のみ（SVG または高解像度 PNG）
- 系列は原則 **2〜3本まで**。モバイル視認性を損なう密集図・多系列図は使わない

**純数字＋色ブロック＋段階リストを優先する场景**（チャートにしない）:

| # | 優先场景 | 表現方法 |
|---|---------|---------|
| 1 | 単一スナップショット値（本日の指数・騰落率・時価総額） | **純数字＋色コーディング**（例 `S&P -0.28%`（赤）） |
| 2 | 単純比較・順位（値上がり/値下がり筆頭、KPI 並列） | **色ブロック分類**（ライトグリーン=騰値上位、ライトピンク=下落上位） |
| 3 | 因果・論理の段階展開（割引率メカニズム等の説明） | **論理的段階リスト**（現状→成長率→予測→バリュエーション導出） |
| 4 | 分類・構造の提示（デュオカード、セクター分類） | **色ブロック＋小ロゴ**、概念図 |
| 5 | 短期変動・粒度が細かすぎるデータ | チャート化せず結論を直接陳述（**テキスト化データ**: 「過去に何度も80%超の下落」） |
| 6 | 象徴的に示せるもの | **象徴的配図**（ブランド実写・概念図でデータを代替） |

> **データ取得**: Phase 0 では従来どおりチャートを収集しない（記事内チャートはフラグのみ）。**視覚設計ブリーフでチャートが必要と判定された场景**に対し、**Phase 3 が能動的に検索・収集**する（履歴データ: Stooq／FRED／Yahoo Finance、既製チャート: 公式 IR・信頼できる金融メディアの高解像度スクリーンショット）。詳細は [../phases/phase3-asset-fetching.md](../phases/phase3-asset-fetching.md)。ロゴ・実写は引き続き共有キャッシュ [../assets/brands/](../assets/brands/) 優先。

### 0.7 共通アニメーション語彙とテンポ

| 効果 | 用途 | テンポ目安 |
|------|------|-----------|
| フェードイン | 句・見出しの登場 | 緩やか（俳句・結論） |
| スライドイン | リスト項目の逐次表示 | 中速（データリスト） |
| ハイライト強調 | 話中のテーマ/ニュースの注目 | 即時（話題と同期） |
| スタイル切替（暗→明＋赤） | コーナー転換のアンカー | 切替点で1回 |

画面持続時間の目安：高密度カード 60-90秒／解説スライド 15-30秒／結論 10-20秒。

### 0.8 企業・メディア・人物画像の使い分け（実写写真ファースト・2026-08-23 改訂）

企業・メディア・人物を画面に出す時は**実写写真ファースト**。ロゴはあくまで補助的な識別要素であり、メインのビジュアルアンカーに据えない（ロゴ単体は平坦でデザイン性がなく、番組の質感を損なう）。素材は共有キャッシュ [`assets/brands/`](../assets/brands/) から（[../infra/brand-asset-cache.md](../infra/brand-asset-cache.md)）。

| 表示コンテキスト | 使う画像（優先順） | 効果 | 主な適用先 |
|---|---|---|---|
| **企業・メディアの単独表示** | ① **社名が写り込む本社ビル・标志性建築物の高解像度実写写真**（`<slug>-hq.jpg`）→ ② 店舗・工場・ロゴ看板の実写 → ③ どうしてもない場合のみロゴを小さく添える | リアリティ・説得力・実在感 | §4 B の個別株深層分析 |
| **人物の発言・見解** | ① **当該発言に紐づく報道記事の写真**（会見・イベント・報道写真）→ ② **本人の高解像度ポートレート写真** | 「誰が言っているか」が伝わる説得力 | §4 各論点の解説（クレイマー氏・トンプソン氏・ボルコウ氏等） |
| **多品牌列挙**（一覧・比較・出所羅列） | 小さなロゴ（背景透過）を**補助的に**配置。可能な限り背景に薄い実写写真や質感のある色面を敷き、ロゴ単体でのっぺりさせない | 視認性＋統一感＋質感 | §2 目玉予告・§5 ニュース速報・セクター一覧 |
| **抽象概念・データ構造** | **文生图（qwen-image-3.0-pro）で生成した高品質な概念図**（金利・割引率・資本構造・K型消費等） | 写真で表現できない論理構造の可視化 | §4 B の概念解説 |

> **鉄則**: メインビジュアルにロゴを据えない。単独クローズアップは**実写建築写真**、人物の論点は**本人・報道写真**、抽象論は**文生图**。ロゴは補助的に小さく使うか、実写・文生图背景の上に添える程度にとどめる。これにより「ロゴだらけの平坦な画面」を排除する。
>
> 実写写真・報道写真の取得は [../phases/phase3-asset-fetching.md](../phases/phase3-asset-fetching.md) の取得フローに従う（公式ニュースルーム → Wikipedia → SearXNG 画像検索）。
